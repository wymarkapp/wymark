Showing and hiding comments is now one plain on/off button, and the source
view has its own switch for the comment markers written in the file. Changes
and comments in the formatted view are quieter and easier to tell apart, and
removed text in a change card is struck through in its colour. Typing while
another app writes to the file no longer loses or moves a keystroke, and a
tool that edits a copy of your file and renames it back no longer undoes what
you wrote in the meantime.

## Highlights

- Comments: the three-way visibility control is one button that shows or
  hides the comment cards (Shift-Cmd-C). In the source view, the comment
  markers in the file can be shown or collapsed from the comment count at the
  foot of the comments column, from the right-click menu, or with Shift-Cmd-M.
- The source view has the same round Comment button under a selection as the
  formatted view.
- In the formatted view, a change is shown as coloured text with a thin
  underline instead of a shaded background, and a commented passage is a
  tint alone, including inside inline code.
- A change card strikes removed text through in the colour of its change, so
  green and blue always mean the same thing in the card as in the document.
- Comments stay readable in dark mode, and the selected comment stands out
  from one you are hovering.
- Fixed: a keystroke typed at the moment another program saved the file could
  be lost, moved, or rolled back.
- Fixed: when a tool edited a copy of your file and renamed it back, text you
  had written in the meantime could be reverted.
