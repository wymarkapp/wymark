Bullets and headings can now fold in the formatted view, so a long outline can
put a section out of sight while you work elsewhere. Documents with many
changes open on their text sooner, and a round of fixes makes review behave
around comments, duplicated blocks and hand-typed closers.

## Highlights

- Fold bullets and headings in the formatted view. Use the chevron, click the
  bullet, or use the editor menu. A fold is only how the document is shown, so
  the file is never touched and the source view never folds. Anything that
  cannot handle a fold opens it, and changes or comments inside a fold are
  counted in grey instead of drawing cards.
- A document with a pending review opens on its text first, and the changes
  paint a moment later.
- With one document in two panes and Show changes on, the other pane now
  paints what you type as you type it.
- Fixed: a strikethrough written with one tilde, like `~text~`, lost a letter
  on screen and wrote extra characters to the file on the next edit.
- Fixed: rejecting a new table or code block now takes its comment thread with
  it.
- Fixed: accepting text added right after a comment no longer puts it inside
  the comment thread.
- Fixed: a block duplicated by pasting now shows as one change, and rejecting
  or accepting it no longer deletes or doubles a comment thread on the original.
- Fixed: a closer typed by hand now ends its formatting in pure mode.
- Fixed: New File and New Folder in the Files panel use the selected folder.
- The window leaves the splash as soon as the app is ready.
- The comment line Wymark writes beside a document now asks to be left out of
  commits.
- Security update to a dependency (Phoenix.HTML 4.4.0).
