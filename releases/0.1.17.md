Quotes and brackets pair only where the text around them allows it, and the
single quote pairs too, in both editors. A zoomed pane remembers the width of
the text and where it stands, so a larger window no longer lengthens the
lines. A
window left hidden for a while no longer comes back as a reloaded page with a
crash report.

## Highlights

- Typing `"` or a bracket pairs only where its neighbours allow it: a
  bracket when what follows is whitespace, a closer or the end of the text,
  a quote when neither neighbour is a letter or digit. Quoting an existing
  word no longer leaves a stray pair on each side of it.
- The single quote `'` pairs and wraps a selection like the other openers,
  in the Formatted and the Source view. An apostrophe inside a word
  (`don't`, `it's`, `dogs'`) is still one character.
- A zoomed pane (the zoom button, Shift-Cmd-Return) remembers the text's
  width and its place between the window's edges. A larger window widens the comments column and never the text; a
  centred text stays centred.
- In a zoomed pane each divider moves its own edge and the other stands still. A
  double-click on the left divider centres the text at the width it has.
- Fixed: a window that had been hidden for a while (a sleeping display,
  another Space) could come back as a reloaded page offering a crash
  report. Nothing had crashed.
- Fixed: the crash dialog printed a piece of its own template where the
  fault belonged.
- Fixed: removing bold or italic from a run left the run uncoloured in the
  Formatted view, while the card named the change.
- Fixed: while a comment was being written, its row on the status chip
  alternated between the count and "comment n/m".
- The left panel's hints (Files, Recents, Search, Outline and the folder
  header's actions) are drawn as the app's own tooltip, not the system's.
